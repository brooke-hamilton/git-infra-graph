# Path-addressed Tree/Blob Node API

<!-- markdownlint-disable MD013 -->

This document specifies the Go API for manipulating a tree of nodes where each node is either a **tree** (container) or a **blob** (leaf with content). Nodes are addressed by **paths**. The API is a set of exported Go functions and types in the `graph` package. Go types are used as parameters and return values.

## Types

```go
// NodeType distinguishes tree nodes from blob nodes.
type NodeType int

const (
    TreeNode NodeType = iota
    BlobNode
)

// NodeResult is returned by Put on success.
type NodeResult struct {
    ID   string   // Hash ID assigned by the storage system
    Path string   // Full path of the node
    Type NodeType // TreeNode or BlobNode
}

// NodeEntry describes a single child in a tree listing.
type NodeEntry struct {
    Name string   // Name of the child node
    Type NodeType // TreeNode or BlobNode
    ID   string   // Hash ID of the child node
}

// NodeContent is returned by Get.
// For a tree node, Children is populated and Blob is nil.
// For a blob node, Blob is populated and Children is nil.
type NodeContent struct {
    ID       string      // Hash ID of the node
    Path     string      // Full path of the node
    Type     NodeType    // TreeNode or BlobNode
    Blob     []byte      // Blob content (only for BlobNode)
    Children []NodeEntry // Immediate children (only for TreeNode)
}
```

## Concepts and invariants

### Node types

- **Tree node**
  - Has a `Name`
  - Has **children** (trees and/or blobs)
  - Has **no blob content**
- **Blob node**
  - Has a `Name`
  - Has **blob content** (`[]byte`)
  - Has **no children** (cannot be a parent)

### Paths

- A node is identified by a **path** made of `/`-separated segments, e.g. `parent1/parent2/child`.
- Each segment corresponds to a node **name** under its parent.

### Name uniqueness

- Names are **unique per parent**, across *both* node types.
- A parent cannot contain both a tree and a blob with the same `Name`.

### IDs

- Each node has a unique `ID` generated by the underlying storage system.
- The `ID` is a **hash**, so a successful write may result in a **new `ID`**.
- The API returns the node `ID` from write operations via `NodeResult`.

### Traversal rule: blobs cannot be parents

- If any **intermediate** path segment resolves to an existing **blob**, the function must return an error (because blobs cannot have children).

## Operations

All operations take a `path string` parameter that identifies the node.

### 1) Put - Create or replace node at path

```go
func Put(path string, blob []byte) (*NodeResult, error)
```

#### Put purpose

- Create or replace the node at `path`.
- If the parent tree path does not exist, **create the whole tree path** (auto-create missing parent trees).

#### Put inputs

- `path`: the full path identifying the node to write.
- `blob`:
  - If `blob` is non-nil, the node at `path` is a **blob node** with that content.
  - If `blob` is nil, the node at `path` is a **tree node**.

#### Put behavior

1. Split `path` into segments.
2. For each **intermediate segment** (all segments except the last):
   - If the segment does not exist: **create a tree node** for it.
   - If the segment exists as a **blob node**: return an **error** (cannot traverse/create beneath a blob).
3. For the **final segment** (the target node at `path`):
   - If it does not exist: create it (tree if `blob` is nil, blob if `blob` is non-nil).
   - If it exists:
     - tree on tree is a **no-op** (`Put` with nil `blob` on an existing tree preserves the tree and all its children)
     - blob to blob replacement is allowed (`Put` with non-nil `blob`)
     - **type conversions are errors**: tree to blob (`Put` with non-nil `blob` on an existing tree) and blob to tree (`Put` with nil `blob` on an existing blob) are both forbidden

#### Put return values

- `*NodeResult` on success, containing:
  - `ID`: the newly stored node hash
  - `Path`: the full node path
  - `Type`: `TreeNode` or `BlobNode`
- `error` on failure.

#### Put error conditions

- A parent path segment resolves to a **blob** ("blobs cannot be parents").
- The target node exists as a **tree**, and the call passes a non-nil `blob` (tree to blob conversion).
- The target node exists as a **blob**, and the call passes nil `blob` (blob to tree conversion).
- Invalid path syntax.

---

### 2) Get - Read node at path

```go
func Get(path string) (*NodeContent, error)
```

#### Get purpose

- Retrieve the node at `path`.

#### Get behavior

- If any **intermediate** segment resolves to a **blob**: return an error (cannot traverse).
- If the node at `path` does not exist: return an error.
- If the node at `path` is a **blob**: return a `*NodeContent` with `Blob` populated.
- If the node at `path` is a **tree**: return a `*NodeContent` with `Children` populated, listing the tree's **immediate children** (each child's `Name`, `Type`, and `ID`).

In effect, `Get(treePath)` returns a directory-style listing.

---

### 3) Delete - Delete node at path (recursive)

```go
func Delete(path string) error
```

#### Delete purpose

- Delete the node at `path`.

#### Delete behavior

- If any **intermediate** segment resolves to a **blob**: return an error (cannot traverse).
- If the node at `path` does not exist: return an error (alternatively, the API may choose idempotent success; if so, document it).
- If the node at `path` is a **blob**: delete it.
- If the node at `path` is a **tree**: **recursively delete** the entire subtree (all descendant trees and blobs).

#### Delete return value

- `error` on failure, `nil` on success.
